# 안드로이드 학생 화면 전송

갤럭시탭 S6 Lite / S5e의 Android 13 사용을 기준으로 만든 학생 앱입니다. 현재 버전은 1.3.0입니다. 최소 Android 8.0(API 26), 대상 API 36이며 Windows 학생 앱과 같은 교사 서버를 사용합니다. 학생이 직접 전송을 시작하고 Android의 화면 공유를 허용해야 동작합니다.

## 설치와 수업 참여

1. 교사 PC에서 `server/서버시작.bat`를 실행하고 수업을 시작합니다.
2. 태블릿을 같은 Wi-Fi에 연결합니다.
3. 태블릿 브라우저에서 `http://교사PC의IP:8080/student`를 엽니다. 예: `http://192.168.0.10:8080/student`. `localhost`는 태블릿 자신을 가리키므로 사용하지 않습니다.
4. **안드로이드 앱 다운로드**를 눌러 APK를 설치합니다. 또는 `android/dist/학생화면전송.apk` 파일만 직접 전달해 설치합니다. 설치 출처 허용이 필요한 경우 학교에서 허용한 절차로 진행합니다. 학교 관리 기기에서 설치가 차단되면 관리 담당자에게 앱 배포를 요청합니다.
5. **학생 화면 전송**을 열고 서버 주소, 수업 코드, 학년·반·번호·이름을 입력합니다.
6. **전송 시작** → 알림 허용 → 화면 공유 창의 **지금 시작**을 누릅니다. Android 13은 기본적으로 전체 화면을 공유합니다. 더 최신 OS에서 공유 범위를 선택하는 창이 나오면 수업에 필요한 범위를 선택하며, 다른 앱으로 이동하는 화면까지 공유하려면 **전체 화면**을 선택합니다.
7. 학습 앱으로 이동합니다. 교사 화면의 학생 타일에서 화면을 확인합니다.
8. 앱의 **전송 중지**, 알림의 **전송 중지**, 교사의 **수업 종료** 중 하나로 끝냅니다. 최근 앱 목록에서 학생 앱을 지워도 중지합니다. 화면 꺼짐·잠금은 대기 상태로 전환하고 잠금 해제 후 전송을 자동으로 이어갑니다. Android가 공유 권한을 종료한 경우에는 **전송 재개**를 눌러 공유를 다시 허용합니다.

## 동작

- **1.3.0 업데이트**: 선생님과 주고받는 기능을 넣었습니다. 선생님이 보낸 안내 문구는 **선생님 메시지** 알림으로 화면 위에 떴다가 앱 화면의 주황 상자에 남습니다(알림 권한이 필요하며 전송 시작 때 이미 받습니다). 메시지에 들어 있는 `https://…`·`www.…` 주소는 파란 링크로 표시되어 누르면 기본 브라우저가 열립니다(알림 문구 자체는 누를 수 없으니 앱을 열어서 누릅니다). 앱의 **✋ 선생님 호출**을 누르면 교사 화면에 손든 표시가 올라가고, 다시 누르거나 선생님이 확인하면 내려갑니다. 손든 상태는 화면 꺼짐·재연결 뒤에도 유지합니다. 캡처 주기(10/20/30초)는 서버가 정하므로 앱 설정이 따로 없습니다.

- **1.2.0 업데이트**: 화면 꺼짐에 따른 앱 자체의 강제 종료를 없앴습니다. 화면이 꺼진 동안 캡처를 쉬고 잠금 해제 시 이전 연결을 교체하여 전송합니다. 같은 학생의 기록과 확대 상태를 유지합니다. 연결이 유지되면 교사 화면에 ‘화면 꺼짐’, 네트워크가 잠들면 ‘재연결 대기’가 표시됩니다.
- Android 15 QPR1 이후처럼 운영체제가 `MediaProjection` 권한을 종료한 경우에는 재허용이 필요합니다. ‘화면 공유 재개 필요’ 알림을 열고 **전송 재개 → 지금 시작**을 누르세요. 앱 프로세스가 살아 있으면 입력 정보를 유지합니다. 강제 종료나 운영체제의 앱 프로세스 제거 이후에는 앱을 열어 다시 참여해야 합니다.

- **1.1.0 업데이트**: 교사가 **AI 분석용 고화질**을 선택하면 원래 화면을 긴 변 최대 2560px, JPEG 품질 85로 별도 저장합니다. Android 13의 화면 공유 허용 방식은 같습니다. 기존 앱 위에 새 APK를 설치해 업데이트합니다.

- 일반 모드: 가로 최대 480px, JPEG 품질 45, 약 2초 간격. 교사가 확대하면 긴 변 최대 1280px, 품질 62, 약 1초 간격.
- 태블릿의 가로·세로 회전에 맞춰 캡처 크기를 변경합니다. 화면 공유 세션을 새로 만들지 않고 기존 가상 디스플레이 크기만 변경합니다.
- Wi-Fi 연결이 일시적으로 끊기면 학생이 허용한 화면 공유 세션 안에서 서버 재접속을 시도합니다. 앱 종료·권한 철회 이후에는 자동으로 전송을 재시작하지 않습니다.
- 앱과 알림에 연결 상태 및 PDF 기록 수집 여부를 표시합니다. 카메라·마이크·파일 접근 권한은 사용하지 않으며, 화면은 태블릿의 파일로 저장하지 않습니다.
- 입력했던 서버 주소와 학생 정보는 앱 내부 설정에 보관합니다. 수업 코드는 다음 앱 실행 시 다시 입력합니다. 앱 데이터 삭제 시 입력값도 사라집니다.
- 서버의 확대, 이전/다음 캡처, PDF 저장은 Windows와 Android에 동일하게 적용됩니다. 캡처 수집 간격은 서버 설정을 따릅니다(기본 30초).
- AI 분석용 수업에서도 실시간 전송은 기존 화질을 유지합니다. 고화질 저장 때만 별도 이미지를 서버에 보내며, 저해상도 이미지를 확대해서 저장하지 않습니다. 고화질 수집 중에는 앱과 알림에 해당 상태가 표시됩니다.
- 이 APK는 iPad용이 아닙니다.

## 연결이 안 될 때

- 서버 주소가 교사 PC의 현재 Wi-Fi IP인지, 수업 코드가 현재 수업의 코드인지 확인합니다.
- 같은 Wi-Fi 이름이어도 학교 AP의 기기 간 통신 차단이 켜져 있으면 접속하지 못할 수 있습니다. 교사 PC 방화벽의 TCP 8080 허용과 학교 네트워크 설정을 담당자에게 확인합니다.
- 화면 공유 권한이 종료되었다는 안내가 나오면 앱에서 **전송 재개**를 누르고 허용합니다. 다른 기기의 중복 학번 접속은 차단하므로 학생 번호도 확인합니다.
- 학교의 관리 정책이나 학습 앱의 보안 정책에 따라 캡처가 차단된 화면은 검게 보일 수 있습니다.
- 다른 앱으로 이동한 뒤 제조사 절전 정책으로 전송이 멈추면 학생 화면 전송 앱의 배터리 사용 제한을 확인합니다. 공유 알림을 허용하면 전송 상태를 쉽게 확인할 수 있습니다.

## 개발·재빌드

준비: JDK 17 이상, Android SDK Platform 36, Build Tools 36.1.0, 인터넷 연결. Gradle 8.13과 필요한 라이브러리는 wrapper가 처음 실행될 때 내려받습니다.

이 PC에는 JDK 17(Temurin)과 Android SDK를 `C:\Users\Public\ScreenMonitor\`에 설치해 두었고 `JAVA_HOME`·`ANDROID_HOME`을 사용자 환경변수로 지정했습니다. 관리자 권한이나 Android Studio는 필요하지 않습니다.

**빌드 경로에 한글이 있으면 안 되는 이유:** 계정 폴더가 `C:\Users\2025-조창현`처럼 한글이면 단위 테스트가 `ClassNotFoundException: GradleWorkerMain`으로 실패합니다. Gradle은 테스트 실행기의 클래스패스를 UTF-8 `@argfile`로 넘기는데, 한국어 Windows의 JDK는 그 파일을 MS949로 읽어 경로가 깨지기 때문입니다(Android Studio 번들 JBR은 이 문제를 피해 갑니다). 그래서 `build-apk.ps1`이 빌드 산출물과 `GRADLE_USER_HOME`을 ASCII 경로(`C:\Users\Public\ScreenMonitor\`)로 옮겨 실행합니다. 프로젝트 폴더 자체는 한글 경로에 그대로 두어도 됩니다.

`안드로이드앱빌드.bat`를 실행하거나 PowerShell에서 다음을 실행합니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build-apk.ps1
```

이 스크립트는 입력값 단위 테스트와 실제 Node 서버/OkHttp 통합 테스트, Android Lint, release 빌드, APK 서명 검증을 수행하고 `dist/학생화면전송.apk`와 SHA-256 파일을 만듭니다. 서버 통합 테스트 때문에 상위 폴더의 `server/`와 테스트용 JPEG가 필요합니다.

OneDrive 동기화가 빌드 중 생성 파일을 잠그는 문제를 피하도록, 소스와 최종 APK는 이 폴더에 유지하고 중간 산출물은 `%LOCALAPPDATA%/ScreenMonitor/build-.../`에 둡니다. Android Studio에서 직접 빌드하면 중간 산출물은 `%TEMP%/screen-monitor-android-.../`에 생성됩니다.

첫 빌드에서 `signing/student-release.jks`와 `keystore.properties`를 만듭니다. 이 두 파일은 교사용 유지보수 자료이므로 학생에게 전달하지 않고 함께 백업하세요. 같은 앱을 업데이트할 때 동일한 서명 키가 필요합니다. 학생에게 전달하는 파일은 `dist/`의 APK 한 개입니다. 버전 업데이트 시 `app/build.gradle`의 `versionCode`를 증가시키세요.

검증 범위: 빌드·서명·정적 호환성 검사와 Windows/Android 동시 접속, 확대 프레임, 이전 캡처, PDF, 중복 학번 차단, 재접속, 수업 종료를 서버 통합 테스트로 확인합니다. 실제 S6 Lite/S5e는 개발 PC에 연결되어 있지 않아 기기에서의 권한 창, 회전, 절전, 장시간 전송은 교실 배포 전에 각 모델 한 대로 확인해야 합니다.

기기 확인 순서: 업데이트 설치 → 화면 공유 허용 → 다른 학습 앱으로 이동 → 교사 화면 확대/이전 캡처 → **선생님 메시지 알림이 학습 앱 위로 뜨는지** → **✋ 선생님 호출이 교사 화면에 뜨고 확인하면 내려가는지** → 화면 꺼짐 10~15분 → 잠금 해제 후 새 화면 수신(손든 상태 유지) → 가로·세로 회전 → Wi-Fi 재연결 → 알림에서 중지 후 잠금 해제(재개되지 않아야 함) → 다시 시작 → 수업 종료. 최신 Android에서는 잠금 후 권한 재요청 안내도 확인합니다.

## 1.4.0 업데이트 (2026-09-23)

서버 주소를 IP 네 칸과 포트 한 칸으로 나눴습니다. 기본값은 192 · 168 · 1 · [빈칸] : 8080입니다. 네 번째 숫자만 입력하며, 다른 네트워크에서는 나머지 숫자도 수정할 수 있습니다. 이전 주소가 저장돼 있으면 그 값을 복구합니다. 도메인·HTTPS 연결은 주소 직접 입력을 선택하세요. 배포 파일명은 학생화면전송.apk입니다.
